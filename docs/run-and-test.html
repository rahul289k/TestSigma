Triangulate · hands-on guide

Run it, look inside, test it yourself

This guide takes you through Triangulate one layer at a time. You run each stage, open what it produced, and check it against the source (the docs, the code, the live app). Then you explore how the layers connect in Neo4j, analyse a real pull request, and check the system's own scorecard. Every command here was run while writing this guide, and the "you should see" numbers are the results it produced.

code decidesAI suggests, code checks

Everything below runs offline: AI answers come from the saved cache in cache/llm/, so you make no Gemini calls and use no quota. The live app (hoppscotch.io), GitHub and your local Neo4j are still contacted. A full pass takes about 30 minutes, most of it the crawl (about 20 minutes) and replaying user journeys (about 9 minutes). The other stages take seconds.

All commands are run from the project folder. They use jq to read the JSON files (preinstalled on macOS 15+, otherwise brew install jq).

0Setup (once)

install
cd ~/Desktop/triangulate
uv venv --python 3.12 .venv
uv pip install --python .venv/bin/python -e ".[dev]"
.venv/bin/python -m playwright install chromium
npm install --prefix src/triangulate/code/node
cp .env.example .env     # then fill in GEMINI_API_KEY and the Neo4j user/password

Neo4j must be running locally (Neo4j Desktop or a server, version 5+). Triangulate only ever deletes its own node types in that database.

check the install
.venv/bin/triangulate --help
.venv/bin/python -m pytest -q
You should see
  • Six commands: run, reason, eval, load, export, review.
  • 38 passed. The Neo4j integration tests use a separate database called triangulate-test.

1Where results go: the run folder

Every run gets a folder runs/<run id>/, and runs/latest always points at the newest one. Each stage writes only its own files there, and Neo4j is rebuilt from these files. So you can open any stage's output in an editor, or with jq as below.

runs/latest/
├── manifest.json          versions pinned, stage fingerprints, confidences used
├── llm_calls.jsonl        every AI call: task, model, cached or live, tokens
├── ingest/                docs → requirements
│   ├── sections.jsonl         315 doc sections
│   ├── requirements.jsonl     116 kept requirements (each with a verbatim quote)
│   └── rejected.jsonl         23 rejected, with the reason
├── code/code_graph.json   components, routes, imports, text keys
├── crawl/                 the live app
│   ├── states.jsonl           243 screens, each with its controls
│   ├── transitions.jsonl      524 clicks: from screen → to screen
│   ├── labels.json            human names for screens (AI)
│   ├── screens/*.jpg          a screenshot per screen
│   └── meta.json              time taken, why each route stopped
├── link/                  joining the layers
│   ├── dom_code.jsonl         control → component, with method and evidence
│   ├── dom_code_unmapped.jsonl  controls not linked, and why
│   ├── req_links.jsonl        requirement → controls (AI judge, verified)
│   ├── gaps.jsonl             why each uncovered requirement is uncovered
│   ├── flows.jsonl            user journeys, replayed in a fresh browser
│   └── review_items.jsonl     questions for a person
├── probe/                 the AI agent's search for missed features
├── reason/pr-6706/        report.html, report.md, impact.json
└── eval/results.json      the scorecard

Set a shell variable for the run you are working on (used by the step-by-step commands):

R=$(readlink runs/latest); echo $R

2Ingestion layer: docs → requirements

pin: codeingest: AI proposes, code verifiesabout 10 s (first time: a few minutes to download the repos)

Pin reads the live app's version (2026.9.0) and downloads exactly that code release and the docs. Ingest splits 26 feature pages into sections, asks the AI for short testable statements, and keeps one only if its quote appears word for word in the section.

run (creates a new run)
.venv/bin/triangulate run --offline --until ingest
R=$(readlink runs/latest)
look at it
jq -c '{app, code: .code.tag, docs: .docs.sha[0:8]}' runs/latest/manifest.json
wc -l runs/latest/ingest/*.jsonl
jq -r .testability runs/latest/ingest/requirements.jsonl | sort | uniq -c
head -1 runs/latest/ingest/requirements.jsonl | jq .
jq -c '{reason, statement}' runs/latest/ingest/rejected.jsonl | head -3
You should see
  • Version 2026.9.0, code tag 2026.9.0, docs 55a3ac54.
  • 315 sections, 116 requirements, 23 rejected (reason: quote not found verbatim in section).
  • 102 UI_OBSERVABLE, 12 NEEDS_LOGIN, 2 NOT_WEB_UI.
  • Each requirement has a statement, the exact quote, the doc url and ui_cues (words to look for on screen).
Test it yourself Pick a requirement and check that its quote is really in the docs: 
jq -r 'select(.id=="REQ-history-e416accb") | .statement, .quote' runs/latest/ingest/requirements.jsonl
grep -n "filter your history" data/repos/docs-*/documentation/features/history.mdx
The grep finds the sentence in the docs source. Try any other id the same way: no kept requirement can have a quote that is missing.

4Crawl layer: exploring the live app

code, no AIabout 20 min

A browser robot opens hoppscotch.io signed out, starts from 7 pages, and clicks every safe control once per page. It never signs in, deletes or leaves the site. A screen is identified by its route plus its visible controls, so the same screen reached twice is stored once.

run
.venv/bin/triangulate run --offline --run $R --start crawl --until crawl
Run one crawl at a time Hoppscotch's MQTT page connects to a public server with a client id every Hoppscotch user shares, so two crawls at once disconnect each other and the results differ.
look at it
jq '{states, transitions, minutes}' runs/latest/crawl/meta.json
jq -c '.per_seed | to_entries[] | {route: .key, screens: .value.states, stopped: .value.stopped}' runs/latest/crawl/meta.json
jq -c '{order, route, path: [.path[].name], controls: (.elements | length)}' runs/latest/crawl/states.jsonl | head -5
jq -c '{from, click: .action.name, to}' runs/latest/crawl/transitions.jsonl | head -5
open runs/latest/crawl/screens/S-0284553ef7c6.jpg
You should see
  • 243 screens and 524 transitions, crawled in about 20 minutes.
  • / and /graphql stopped at route_cap (60 screens each). The other five routes stopped as explored: nothing new left to click. No route should say time.
  • Each screen lists the click path that first reached it, for example ["Import / Export"].
  • The screenshot is the REST page, the first screen.
Test it yourself Open hoppscotch.io in a private window, follow the path of any screen (for example screen 41 is /settings with no clicks), and compare what you see with its screenshot and its elements list: 
jq -r 'select(.order==41) | .route, .screenshot, (.elements[] | "\(.role)\t\(.name)")' runs/latest/crawl/states.jsonl | head -15

5Connecting a button to its code

label: AI (names only)load + DOM→code: codeabout 10 s

Label names each screen for humans. Load puts everything into Neo4j so the next steps can search it. DOM→code links each control to the component that draws it: visible text → text key → components that use the key → only those that can appear on this page → the best match by neighbouring labels.

run
.venv/bin/triangulate run --offline --run $R --start label --until domcode
look at it
jq -r 'to_entries[0:5][] | "\(.key)  \(.value.label)"' runs/latest/crawl/labels.json
jq -r .method runs/latest/link/dom_code.jsonl | sort | uniq -c
jq -c 'select(.name=="Wrap lines" and .route=="/") | {area: .context, component: .components[0].component, method, evidence}' runs/latest/link/dom_code.jsonl
jq -r .reason runs/latest/link/dom_code_unmapped.jsonl | sort | uniq -c | sort -rn | head -3
You should see
  • Link methods: 298 i18n_route_unique (one candidate on the page: certain), 331 i18n_route_tiebreak, 65 i18n_route_ambiguous, 17 + 22 global. That is 733 of 1,044 controls (70%).
  • "Wrap lines" on the REST page appears in three places, each linked to a different component: JSONLensRenderer.vue in the main area, ResponseInterface.vue in the side panel and ImportCurl.vue in the Import cURL dialog. The evidence field explains each one: used by 29 component(s), 26 on route /; tie-break scores …
  • 180 controls are not linked because their text is not a translated string (user data, examples).

6Requirements → screens, gaps and user journeys

judge + probe: AI, checked by codegaps + flows: codeabout 9 min (journey replays)

For each requirement, the graph is searched for likely controls, and the AI judge says whether they implement it. It may only cite controls it was shown. The probe agent then hunts in the live app for features still missing. Every uncovered requirement gets one gap reason, and every covered one gets a user journey that is replayed in a fresh browser to prove it.

run (to the end)
.venv/bin/triangulate run --offline --run $R --start judge
look at it
jq -r .ui_verdict runs/latest/link/req_links.jsonl | sort | uniq -c
jq -c 'select(.req_id=="REQ-history-e416accb") | {ui_verdict, ui_elements, ui_rationale}' runs/latest/link/req_links.jsonl
jq -r .kind runs/latest/link/gaps.jsonl | sort | uniq -c
jq -c 'select(.name | startswith("Filter history")) | {name, start_route, clicks: [.steps[].name], target: .target_name, replay_verified}' runs/latest/link/flows.jsonl
jq -c '{req_id, outcome, decisions: (.steps | length)}' runs/latest/probe/episodes.jsonl
jq -c '{trigger, question}' runs/latest/link/review_items.jsonl
You should see
  • Judge verdicts: 51 COVERED, 32 PARTIAL, 19 NOT_FOUND, 12 NOT_APPLICABLE (need sign-in).
  • The history-filter requirement is linked to two "Filter" controls.
  • Gaps: 19 UNOBSERVED_IN_UI (built, not reached), 12 OUTSIDE_CRAWL_BOUNDARY (sign-in), 2 NOT_UI_TESTABLE.
  • The journey "Filter history items in the history section" starts on /, clicks Send, and reaches the target control Filter, with replay_verified: true.
  • 5 open questions for a person.
Test it yourself Replay a journey by hand: open hoppscotch.io, click Send, then find Filter. Then pick a requirement with a gap and check that the screen really was not reached (for example, collection actions need a saved collection, which a signed-out visitor does not have).

7See the relations in Neo4j

Open http://localhost:7474 (Neo4j Browser), sign in with the user and password from .env, and paste a query into the top bar. Queries that return p (a path) are drawn as a graph, and the others as a table.

One run at a time Neo4j holds the graph of the last run that was loaded. run, reason, eval and load each replace it. To look at a specific run: .venv/bin/triangulate load --run <run id>.

a · What is in the graph

You should see3,739 Symbol, 2,198 I18nKey, 1,044 Element, 756 File, 335 Component, 315 Section, 243 State, 116 Requirement, 112 Flow, 33 Gap and a few more.

b · One requirement, end to end

MATCH (r:Requirement {id: 'REQ-history-e416accb'})-[c:COVERED_BY]->(e:Element)<-[:CONTAINS]-(s:State)
RETURN r.statement AS requirement, e.label AS control, c.confidence AS confidence,
       collect(DISTINCT s.label)[0..3] AS screens
as a picture: requirement → control → code
MATCH p = (r:Requirement {id: 'REQ-history-e416accb'})-[:COVERED_BY]->(:Element)-[:IMPLEMENTED_BY]->(:Component)
RETURN p

c · A button and the code that draws it, with the evidence

MATCH (e:Element {label: 'Wrap lines'})-[i:IMPLEMENTED_BY]->(c:Component)
RETURN e.route AS route, e.context AS area, c.id AS component, i.method AS method,
       i.confidence AS confidence, i.evidence AS evidence ORDER BY route LIMIT 10
as a picture: the text-key bridge
MATCH p = (e:Element {label: 'Wrap lines', route: '/'})-[:DISPLAYS]->(k:I18nKey)<-[:USES_KEY]-(c:Component)
RETURN p LIMIT 30

d · Absence: what is missing, and why

MATCH (r:Requirement)-[:HAS_GAP]->(g:Gap)
OPTIONAL MATCH (g)-[:EXPECTED_IN]->(c:Component)
RETURN g.kind AS gap, r.statement AS requirement, collect(c.id)[0..2] AS expected_in ORDER BY gap
the honesty check: must return no rows
MATCH (r:Requirement)
WITH r, EXISTS { (r)-[:COVERED_BY]->() } AS covered, EXISTS { (r)-[:HAS_GAP]->() } AS gap
WHERE covered = gap RETURN r.id

Every requirement is either covered or has exactly one gap. Zero rows means none is silently unlinked.

e · A user journey, step by step

MATCH (f:Flow)-[s:STEP]->(e:Element) WHERE f.name STARTS WITH 'Filter history'
RETURN f.name AS journey, s.order AS step, e.label AS control ORDER BY step

f · How screens connect (the crawl as a graph)

MATCH p = (:State {route: '/settings'})-[:TRANSITION]->(:State) RETURN p LIMIT 50

g · The code side: who draws a component, who imports a file

MATCH (p:Component)-[:RENDERS]->(c:Component) WHERE c.id ENDS WITH 'JSONLensRenderer.vue'
RETURN p.id AS drawn_by
MATCH (f:File {path: 'src/helpers/editor/linting/jsoncPretty.ts'})<-[:IMPORTS*1..2]-(g:File)
RETURN DISTINCT g.path AS importer

8Analyse a pull request

impact: codereport text: AI, checked by codeabout 10 s

reason fetches the PR from GitHub, maps its changed lines to components, walks the graph outward (controls → screens → journeys → requirements), and writes a report. It also stores the PR in Neo4j, so you can query its blast radius directly.

run
.venv/bin/triangulate reason 6706 --offline
open runs/latest/reason/pr-6706/report.html
look at it
jq '.summary' runs/latest/reason/pr-6706/impact.json
jq -c '.changes[] | {file, kinds}' runs/latest/reason/pr-6706/impact.json
jq -c '.elements[] | {label, band, risk}' runs/latest/reason/pr-6706/impact.json | head -6
jq -r '.flows[].name' runs/latest/reason/pr-6706/impact.json
You should see
  • Overall risk Medium: 6 screens, 1 journey to retest, 1 requirement at risk, 1 question, 2 changes not connected to a screen.
  • Changed files include JSONLensRenderer.vue (template and script) and jsoncPretty.ts.
  • Five Medium controls (Filter, More, Wrap lines, …) with risk 0.63, and the journey "Filter history items in the history section".

The same blast radius as a graph query

MATCH (pr:PullRequest {number: 6706})-[ch:CHANGES]->(f:File)
MATCH p = (f)<-[:IMPORTS*0..3]-(g:File)<-[:DEFINED_IN]-(c:Component)
MATCH (e:Element)-[impl:IMPLEMENTED_BY]->(c)
WITH e, impl.confidence * ch.weight * (0.7 ^ (length(p) - 1)) AS risk
MATCH (st:State)-[:CONTAINS]->(e)
OPTIONAL MATCH (fl:Flow)-[:STEP]->(e)
OPTIONAL MATCH (r:Requirement)-[:COVERED_BY]->(e)
RETURN e.label AS control, max(risk) AS risk, collect(DISTINCT st.label)[0..3] AS screens,
       collect(DISTINCT fl.name) AS journeys, collect(DISTINCT r.id) AS requirements
ORDER BY risk DESC

This raw query lists 8 controls. The report applies one more rule, presence: a component only counts as being on a screen if a control there is uniquely linked to it, or at least two of its controls are. That is why "Wrap lines" on the code-generation screen appears here but not in the report.

Test it yourself Open the PR's diff on GitHub, find the change to JSONLensRenderer.vue, and check that the report's screens are the ones that show the JSON response viewer. The other samples: 6584 (desktop-only, so Low), 6707 and 6708 (code the crawl never displayed, so Low with a question), and 6721 (Medium, cURL code generation).

9Check it is right: the scorecard

The eval runs 10 automatic checks and compares the run against three hand-checked answer sets in eval/gold/. The verdict is "correct" only if every check passes and every score meets eval/thresholds.yaml. It needs the five PR reports, so run reason for each one first.

run
for pr in 6584 6706 6707 6708 6721; do .venv/bin/triangulate reason $pr --offline > /dev/null; done
.venv/bin/triangulate eval
look at it
jq '.verdict' runs/latest/eval/results.json
jq -c '.invariants[] | {invariant, ok}' runs/latest/eval/results.json
jq '.dom_code.precision_by_method, .req_ui' runs/latest/eval/results.json
jq -c '.prs[] | {pr, overall_risk, false_alarms, recall}' runs/latest/eval/results.json
You should see
  • The last line printed is run is correct (invariants + eval/thresholds.yaml), and the exit code is 0.
  • Button → code: certain links 1.00 precision, all links 0.69. Requirement → screen: precision 0.84, recall 0.76.
  • PRs: no false alarms. PR 6706 finds 3 of 5 expected controls (misses Copy and Download file).
Test it yourself Open eval/gold/dom_code.yaml, pick an item, find the element in runs/latest/link/dom_code.jsonl, and read the component's template to judge the link yourself. Or raise a threshold in eval/thresholds.yaml above the measured score and run eval again: the verdict names the failing score and the command exits with 1.

10Repeatability: same input, same output

Every stage's output gets a fingerprint (hash), and every AI answer is saved by a fingerprint of its question. So two offline runs of the same release should match stage by stage. Run the pipeline a second time, then compare:

FIRST=$R
.venv/bin/triangulate run --offline
SECOND=$(readlink runs/latest)
.venv/bin/triangulate eval --run $SECOND --compare $FIRST
jq '.repeatability.matches, .repeatability.llm_calls' runs/$SECOND/eval/results.json
You should see true for ingest, code, crawl, link and probe, and "live": 0 AI calls. Screenshots and on-screen pixel positions are not part of the fingerprint, because a banner such as Hoppscotch's "offline" notice can move the page without changing any control.

11Human review (optional)

Open questions from step 6 can be answered by a person. Answers are saved in config/overrides.yaml and reused by every later run (with method human and confidence 1.0).

.venv/bin/triangulate review
.venv/bin/triangulate run --offline --run $R --start domcode
This changes later runs An override changes the links, so later runs no longer match the shipped results exactly, and the offline cache may miss. To undo it, empty config/overrides.yaml again.

12A live run with your own Gemini key (optional)

Without --offline, any AI question not in the cache goes to Gemini. With unchanged inputs everything is still served from the cache. A run from an empty cache needs about 15 calls; the Gemini free tier allows about 20 per model per day.

.venv/bin/triangulate run                      # full run, live where needed
.venv/bin/triangulate run --profile smoke      # small run: 3 doc pages, 2 routes, about 10 calls
jq -c '{task, model, cached}' runs/latest/llm_calls.jsonl

If Google reports the daily quota as used up, the run stops with a clear message and keeps everything cached. Resume after the reset with --run <run id> --start <stage>.

13Troubleshooting

You seeMeaningDo this
CacheMiss in an offline runAn AI question differs from the recorded ones: the code, config or live app changed.Find the cause with eval --compare, or run once live to record new answers.
Neo4j connection refusedNeo4j is not running, or .env has the wrong address or password.Start Neo4j and check NEO4J_URI, NEO4J_USER and NEO4J_PASSWORD.
App version changed during the crawlHoppscotch deployed a new release mid-run, so the run is invalid by design.Run again: it pins the new version (AI answers for new content are live).
Crawl results differ between runsTwo crawls ran at the same time (the MQTT page), or the live site changed.Run crawls one at a time. eval --compare shows which stage differs.
Executable doesn't exist (Playwright)The Chromium browser is not installed..venv/bin/python -m playwright install chromium
run is NOT correct: PR … has no reportThe eval needs the five PR reports.Run reason for 6584, 6706, 6707, 6708 and 6721 first (step 9).
